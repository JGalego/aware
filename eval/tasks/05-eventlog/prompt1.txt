The inventory code in this repo (events, store, projections, snapshot, api, report) has several bugs. Reports from users: (1) reserving exactly as many units as are available is rejected with OutOfStock; (2) after an order ships, that item's available count stays too low, as if the shipped units were still reserved; (3) an order that reserves the same item twice only holds the second quantity; (4) shipping an order that was never reserved, or that already shipped, is accepted and logged, but it should raise KeyError(order) just like release() does; (5) low_stock(state, threshold) should list items whose available quantity is at or below threshold, but it gets both the quantity and the comparison wrong; (6) after rebuilding a state from a snapshot and applying more events, the snapshot itself has changed, so a second rebuild from the same snapshot gives different numbers. Find and fix all six.
