The router in this repo (response, converters, route, router) has several bugs. (1) Literal parts of a pattern are not escaped: '/files/report.pdf' also matches '/files/reportXpdf'. (2) The first registered route wins when several match, so '/users/<id>' registered before '/users/me' shadows it; the docstring says the route with the fewest parameters wins, then the first registered. (3) The 405 response lists every method of every route in its Allow header, but it must list only the methods the requested path accepts. (4) url_for does not percent-encode values (a str value 'a b/c' must become 'a%20b%2Fc', a path value 'dir/a b.txt' must become 'dir/a%20b.txt'). (5) Middleware run in the wrong order: the first one registered must be the outermost. (6) A handler raising HTTPError(404, 'no such user') should answer 404 'no such user', but every exception becomes a 500, and middleware must still see whichever response was produced. (7) The int converter accepts '-5' and '+5'-style input; it should accept digits only, so '/items/-5' is a 404. Find and fix all seven.
